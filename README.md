# Smoke 💨

Высокопроизводительный, легковесный DPI-bypass прокси для Windows, написанный на **Rust** (Tokio).

Разработан по принципу **«Запустил — и всё работает» (Zero-Config)**: обходит блокировки и замедления ТСПУ (YouTube, Discord и др.) без необходимости устанавливать сторонние драйверы (WinDivert), без прав администратора и без сложных настроек.

1. Скачайте **`smoke.exe`** из раздела [Releases](https://github.com/Akdered/Smoke/releases).

## ⚡ Ключевые возможности v0.5.0

### 1. 💾 Автосохранение обученных стратегий на диск (Persistent Cache)
- Smoke автоматически сохраняет найденные успешные стратегии для каждого домена в файл `%LOCALAPPDATA%\Smoke\cache.json`.
- При повторном запуске прокси стартует с готовой картой сети: видео в 4K и чаты открываются на максимальной скорости вашего канала с **0 мс задержки на обучение**.

### 2. 🛡 Блокировка QUIC (HTTP/3 UDP) в 1 клик без прав администратора
- Браузеры на базе Chromium (Chrome, Edge, Яндекс, Brave) по умолчанию пытаются воспроизводить видео через протокол QUIC (UDP 443). В РФ провайдеры часто «душат» UDP с потерей 70% пакетов, из-за чего видео буферизируется и зависает на первых секундах.
- Smoke на время своей работы автоматически выставляет локальную политику браузеров `QuicAllowed = 0` в ветке текущего пользователя `HKCU`, принуждая браузер сразу использовать стабильный и быстрый TCP-трафик через десинхронизатор. При выходе из программы исходные параметры мгновенно восстанавливаются.

### 3. 🌐 Многоуровневый Disorder (TTL = 1, 2, 3)
- Классический трюк Disorder с `TTL=1` часто погибает на домашнем роутере, если у пользователя стоит цепочка из GPON-терминала и личного Wi-Fi роутера (Keenetic, ASUS, TP-Link).
- В Smoke v0.5.0 внедрен каскад `Disorder1` (TTL=1), `Disorder2` (TTL=2) и `Disorder3` (TTL=3), что позволяет пробивать ТСПУ сквозь любую сложность домашних маршрутизаторов.

### 4. 🎮 Полная оптимизация для Discord (включая обновления и шлюз)
- **Приоритет `Disorder1 / Disorder2` для Discord**: Для всех доменов семейства Discord по умолчанию используются специализированные техники с наивысшей пробиваемостью (более 95% у провайдеров РФ).
- **Семейное связывание (Domain Family Cache)**: Успешная стратегия для одного сервиса Discord автоматически распространяется на `gateway.discord.gg`, `cdn.discordapp.com` и апдейтер.
- **In-Flight Fast Failover**: Если первый запрос зависает или сбрасывается ТСПУ, Smoke не разрывает связь с Discord, а мгновенно открывает новый сокет и меняет технику за 1 секунду.

> 💡 **Если в голосовом канале Discord висит «Подключение RTC» (RTC Connecting):**
> 1. В Discord откройте: **Настройки пользователя** -> **Голос и видео**.
> 2. Прокрутите вниз и выключите: **«Включить приоритет качества обслуживания (QoS)»**.
> 3. Если проблема сохраняется, попросите админа сервера сменить регион голосового канала на **«Central Europe»** или **«Rotterdam»**.

## 🛠 Арсенал техник обхода (13 алгоритмов)

| № | Стратегия | Описание механизма | Рекомендуется для |
|---|-----------|--------------------|-------------------|
| 1 | **`Disorder1`** | 1-й байт с `TTL=1`, ретрансмит через TCP SACK | Discord, мобильные сети (прямое подключение) |
| 2 | **`Disorder2`** | 1-й байт с `TTL=2`, ретрансмит через TCP SACK | Сети за домашними роутерами и GPON-модемами |
| 3 | **`TlsRecordFrag`** | Разрез ClientHello на 3–4 TLS-рекорда (RFC 8446) | Ростелеком, Дом.ру, ШПД |
| 4 | **`TlsRecordFrag2`** | 2-звенный разрез (1-й байт handshake payload в 1-м рекорде) | Высокая совместимость со всеми CDN |
| 5 | **`TlsRecordFragSni`** | Граница TLS-рекорда перед полем SNI | Силат, EcoFilter |
| 6 | **`DisorderSni`** | Disorder-разрез до середины имени домена SNI с `TTL=1` | Жесткие мобильные ТСПУ |
| 7 | **`DisorderSni2`** | Disorder-разрез до середины SNI с `TTL=2` | ТСПУ за домашним NAT |
| 8 | **`OobSni`** | Инъекция TCP Urgent Pointer (Out-of-Band байта) в середине SNI | Сигнатурный DPI |
| 9 | **`TcpSplitSni`** | Чистый TCP-сплит точно по центру имени хоста SNI | Низкий MTU |
| 10 | **`Combo`** | Двухзвенная фрагментация TLS-рекордов + TCP Disorder | Упорные блокировки |
| 11 | **`Disorder3`** | 1-й байт с `TTL=3` | Глубокие корпоративные/домашние сети |
| 12 | **`TcpSplit2`** | TCP-сплит после первых 2 байт заголовка TLS (`0x16 0x03`) | Классический сплит |
| 13 | **`TcpSplit1`** | TCP-сплит после 1-го байта | Базовая сегментация |

## ⚙ Параметры командной строки

```text
Usage: smoke.exe [OPTIONS]

Options:
  -b, --bind <BIND>          Адрес и порт для запуска прокси [default: 127.0.0.1:1080]
  -p, --preset <PRESET>      Пресет обхода [default: auto] 
                             [possible values: auto, rtk, mobile, discord, ultra]
  -s, --strategy <STRATEGY>  Принудительно зафиксировать одну стратегию 
      --allow-quic           Разрешить протокол QUIC в браузерах (по умолчанию блокируется)
  -m, --minimized            Скрыть окно консоли и работать в фоновом режиме
      --scan                 Запустить предварительный бенчмарк сети перед стартом
      --no-sysproxy          Не включать системный прокси Windows (только SOCKS5/HTTP на 1080)
      --clean                Экстренно отключить системный прокси Windows и выйти
  -v, --verbose              Подробный вывод логов (DEBUG)
  -h, --help                 Показать справку
  -V, --version              Показать версию
```

### Примеры:

1. **Обычный запуск (рекомендуется всем)**:
   ```powershell
   smoke.exe
   ```

2. **Запуск в скрытом/фоновом режиме**:
   ```powershell
   smoke.exe --minimized
   ```

3. **Запуск с явным пресетом под Discord**:
   ```powershell
   smoke.exe --preset discord
   ```

4. **Экстренный сброс настроек сети Windows**:
   ```powershell
   smoke.exe --clean
   ```
