# Smoke 💨

Высокопроизводительный, легковесный DPI-bypass прокси для Windows, написанный на **Rust** (Tokio).

Разработан по принципу **Zero-Config**: обходит блокировки и замедления ТСПУ (YouTube, Discord и др.) без необходимости устанавливать сторонние драйверы (WinDivert), без прав администратора и без сложных настроек.

## ⚡ Особенности и методы обхода (архитектура устойчивости)

Разные провайдеры в РФ (Ростелеком, МТС, Билайн, Мегафон, Дом.ру, региональные сети) используют разное "железо" ТСПУ (РДУ/EcoFilter от RDP.RU, Силат и др.) с разными алгоритмами инспекции пакетов. Smoke реализует многоуровневый арсенал обхода:

1. **`TlsRecordFrag` (Многозвенная фрагментация TLS Record)**:
   - Разбивает тело TLS ClientHello на 3–4 валидных TLS Record'а (по спецификации RFC 8446 §5.1).
   - ТСПУ ожидает увидеть полный ClientHello в одном рекорде. Ни один отечественный ТСПУ не производит сборку TLS Record Layer на аппаратном уровне. В результате сигнатура блокировки не срабатывает.
2. **`TlsRecordFrag2` (Двухзвенная фрагментация — эталон совместимости)**:
   - Первый TLS Record содержит ровно **1 байт** Handshake payload (тип `0x01 ClientHello`).
   - Второй TLS Record содержит всё остальное (длину, случайные байты, шифры и SNI).
   - В 1-м рекорде ТСПУ не находит SNI (пакет слишком короткий). Во 2-м рекорде ТСПУ видит лишь continuation payload и не ищет SNI. Любой веб-сервер (Google GFE, Cloudflare) собирает этот запрос штатно.
3. **`TlsRecordAndSni` (Двойной TCP-сплит)**:
   - Сегмент 1: первые 2 байта заголовка TLS (`0x16 0x03`).
   - Сегмент 2: данные до середины SNI.
   - Сегмент 3: хвост запроса.
   - Сбивает ТСПУ, анализирующие только первый TCP-пакет на наличие заголовка `0x16 0x03 0x01`.
4. **`SniMiddle` (TCP-сплит по центру домена)**:
   - Разрезает TCP-поток ровно пополам внутри имени домена (`googlevideo.com`, `youtube.com`). Идеально для мобильных сетей с жестким MTU.
5. **HTTP Host Desync**:
   - Автоматический разрез незашифрованных HTTP-запросов (порт 80) внутри заголовка `Host:` (`\r\nHo` + `st: ...`).
6. **Anti-Coalescing Micro-Sleep**:
   - Паузы 1-2 мс между отправкой сегментов предотвращают их объединение сетевой картой (TSO/LSO).
7. **Каскадный шифрованный DoH (IPv4-Only)**:
   - Google DoH -> Cloudflare DoH -> Quad9 DoH -> Системный DNS.
   - Защищает от DNS-подмены локальных IP-адресов GGC (Google Global Cache) на замедленные узлы.

## 🛠 Параметры командной строки

```text
Usage: smoke-cli.exe [OPTIONS]

Options:
  -b, --bind <BIND>          Адрес и порт для запуска прокси [default: 127.0.0.1:1080]
  -s, --strategy <STRATEGY>  Стратегия десинхронизации [default: auto] 
                             [possible values: auto, tls-record-frag, tls-record-frag2, tls-record, sni-middle, none]
      --no-sysproxy          Не включать системный прокси Windows (для ручной настройки)
  -v, --verbose              Подробный вывод логов (DEBUG)
  -h, --help                 Показать справку
  -V, --version              Показать версию
```

Options:
  -b, --bind <BIND>          Адрес и порт для запуска прокси [default: 127.0.0.1:1080]
  -s, --strategy <STRATEGY>  Стратегия десинхронизации [default: auto] 
                             [possible values: auto, tls-record, sni-middle, fake-ttl, none]
      --fake-ttl <FAKE_TTL>  TTL для стратегии fake-ttl [default: 3]
      --no-sysproxy          Не включать системный прокси Windows (для ручной настройки)
  -v, --verbose              Подробный вывод логов (DEBUG)
  -h, --help                 Показать справку
  -V, --version              Показать версию
```

### Примеры использования:

1. **Принудительный мощный режим двойного сплита**:
   ```powershell
   smoke-cli.exe --strategy tls-record
   ```

2. **Режим с обманом ТСПУ через малый TTL**:
   ```powershell
   smoke-cli.exe --strategy fake-ttl --fake-ttl 3
   ```

3. **Запуск без изменения настроек Windows (только локальный SOCKS5)**:
   ```powershell
   smoke-cli.exe --no-sysproxy --bind 127.0.0.1:1080
   ```
   *(Удобно для настройки только конкретного приложения, например Telegram: SOCKS5 `127.0.0.1:1080`)*

## 📦 Сборка релизной версии

Для сборки максимально оптимизированного бинарного файла:

```powershell
cargo build --release
```

Файл будет доступен по пути `target/release/smoke-cli.exe` (размер ~3.6 МБ, статически слинкован, без внешних DLL-зависимостей кроме стандартных системных библиотек Windows).
