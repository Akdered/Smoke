# Smoke 💨

Высокопроизводительный, легковесный DPI-bypass прокси для Windows, написанный на **Rust** (Tokio).

Разработан по принципу **«Запустил — и всё работает» (Zero-Config)**: обходит блокировки и замедления ТСПУ (YouTube, Discord и др.) без необходимости устанавливать сторонние драйверы (WinDivert), без прав администратора и без сложных настроек.

## 🚀 Быстрый старт (для обычного пользователя)

1. Скачайте **`smoke.exe`** из раздела [Releases](https://github.com/Akdered/Smoke/releases).
2. Запустите двойным кликом.
3. **Готово!** YouTube, Discord и заблокированные сайты работают сразу во всей системе.

## 🎮 Специальная оптимизация для Discord (включая обновления и шлюз)

Discord использует сложную инфраструктуру: отдельный апдейтер Squirrel (`Update.exe`), шлюзы WebSocket (`gateway.discord.gg`), CDN медиа (`cdn.discordapp.com`) и голосовые серверы (`*.discord.media`).

В версии **v0.4.1** добавлены ключевые улучшения для Discord:
1. **Приоритет `Disorder1` для Discord**: Для всех доменов семейства Discord по умолчанию используется проверенная техника `Disorder1` (ByeDPI/Zapret-трюк с TTL=1 и инверсией порядка пакетов через SACK), которая пробивает блокировки Discord более чем у 95% провайдеров.
2. **Семейное связывание (Domain Family Cache)**: Как только получен ответ от одного сервиса Discord (например, при проверке обновлений), все остальные домены (`gateway.discord.gg`, `cdn.discordapp.com`) мгновенно подключаются по найденной рабочей стратегии без задержек.
3. **In-Flight Fast Failover**: Если первый запрос зависает или сбрасывается ТСПУ, Smoke **не разрывает связь с Discord**! Прокси моментально открывает новое соединение к серверу, меняет стратегию и отправляет запрос повторно за 1 секунду. Приложение Discord никогда не видит ошибку "Update Failed" или вечный спиннер.

> 💡 **Если в голосовом канале Discord висит «Подключение RTC» (RTC Connecting):**
> 1. В Discord откройте: **Настройки пользователя** -> **Голос и видео**.
> 2. Прокрутите вниз и выключите: **«Включить приоритет качества обслуживания (QoS)»**.
> 3. Если проблема сохраняется, попросите админа сервера сменить регион голосового канала на **«Central Europe»** или **«Rotterdam»**.

## ⚡ Что под капотом: Smart Adaptive Engine & Арсенал из 10 техник

У разных провайдеров в РФ (Ростелеком, МТС, Билайн, Мегафон, Дом.ру, региональные провайдеры) установлены разные типы ТСПУ (РДУ / EcoFilter от RDP.RU, Силат и др.) с абсолютно разной чувствительностью к сегментации пакетов.

- **Старт за 2 мс**: Никаких долгих предварительных сканирований перед запуском.
- **Обучение на лету**: Smoke анализирует ответы серверов. При сбросе ТСПУ движок мгновенно перебирает стратегии из арсенала и запоминает рабочую для семейства доменов.
- **Сквозная оптимизация Google Video**: Как только найден ключ к одному узлу CDN, все видеопотоки автоматически ускоряются на максимальной скорости вашего канала.

### Арсенал техник обхода:

| № | Стратегия | Описание механизма | Эффективность |
|---|-----------|--------------------|---------------|
| 1 | **`Disorder1`** | Отправка 1-го байта с умирающим `TTL=1` (ByeDPI-трюк). ТСПУ получает сегменты в обратном порядке из-за SACK | Топ для Discord и мобильных сетей |
| 2 | **`TlsRecordFrag`** | Разрез ClientHello на 3–4 валидных TLS-рекорда (RFC 8446 §5.1) | Универсальный для Ростелеком, Дом.ру |
| 3 | **`TlsRecordFrag2`** | 2-звенный разрез: ровно 1 байт типа ClientHello в первом рекорде | Высокая совместимость со всеми CDN |
| 4 | **`TlsRecordFragSni`** | Граница TLS-рекорда выставляется непосредственно перед полем SNI | Пробивает Силат и EcoFilter |
| 5 | **`DisorderSni`** | Disorder-разрез до середины имени домена SNI с `TTL=1` | Пробивает жесткие мобильные ТСПУ |
| 6 | **`OobSni`** | Инъекция TCP Urgent Pointer (Out-of-Band байта) в середине SNI | Обход сигнатурного DPI |
| 7 | **`TcpSplitSni`** | Чистый TCP-сплит точно по центру имени хоста SNI | Идеально при низком MTU |
| 8 | **`TcpSplit2`** | TCP-сплит после первых 2 байт заголовка TLS (`0x16 0x03`) | Классический сплит |
| 9 | **`TcpSplit1`** | TCP-сплит после 1-го байта | Базовая сегментация |
| 10 | **`Combo`** | Двухзвенная фрагментация TLS-рекордов + TCP Disorder | Ультимативный режим против упорных блокировок |

## 🛠 Параметры командной строки (для продвинутых)

```text
Usage: smoke.exe [OPTIONS]

Options:
  -b, --bind <BIND>          Адрес и порт для запуска прокси [default: 127.0.0.1:1080]
  -p, --preset <PRESET>      Пресет обхода [default: auto] 
                             [possible values: auto, rtk, mobile, discord, ultra]
  -s, --strategy <STRATEGY>  Принудительно зафиксировать одну стратегию 
                             [possible values: tls-record-frag, tls-record-frag2, tls-record-frag-sni, 
                              disorder1, disorder-sni, oob-sni, tcp-split1, tcp-split2, tcp-split-sni, combo, none]
      --scan                 Запустить предварительный бенчмарк сети перед стартом
      --no-sysproxy          Не включать системный прокси Windows (только SOCKS5/HTTP на 1080)
      --clean                Экстренно отключить системный прокси Windows и выйти
  -v, --verbose              Подробный вывод логов (DEBUG)
  -h, --help                 Показать справку
  -V, --version              Показать версию
```

### Примеры:

1. **Обычный запуск (рекомендуется всем)**:
   ```powershell
   smoke.exe
   ```

2. **Запуск с явным пресетом под Discord**:
   ```powershell
   smoke.exe --preset discord
   ```

3. **Запуск с явным пресетом под мобильного оператора**:
   ```powershell
   smoke.exe --preset mobile
   ```

4. **Запуск только как SOCKS5 без настройки системного прокси**:
   ```powershell
   smoke.exe --no-sysproxy
   ```

5. **Экстренный сброс настроек сети Windows**:
   ```powershell
   smoke.exe --clean
   ```
